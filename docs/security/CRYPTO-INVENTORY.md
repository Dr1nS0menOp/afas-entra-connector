# Cryptographic inventory and key management

Covers OWASP ASVS 5.0 V11.1.1 (key management) and V11.1.2 (inventory). Update this file
whenever a key, algorithm, library or certificate changes. Last reviewed 2026-11-01
(version 0.10.0).

## Libraries

| Library | Used for | Notes |
| --- | --- | --- |
| rustls 0.23 with aws-lc-rs | All outbound TLS | TLS 1.3 only by default; post-quantum hybrid key exchange preferred |
| aws-lc-rs (AWS-LC) | TLS primitives, HMAC-SHA-256 (webhook), RS256 signing (via jsonwebtoken), RSA key generation (via rcgen) | AWS-LC is the library behind AWS's FIPS 140-3 validated module; this build uses the standard, non-FIPS variant |
| rustls-platform-verifier | Server certificate validation | The operating system's trust store |
| jsonwebtoken (aws-lc-rs backend) | Client assertion for Entra (RFC 7523) | RS256 |
| rcgen (aws-lc-rs backend) | Certificate created by the installer | RSA 3072, SHA-256 |
| sha1, sha2 (RustCrypto) | Certificate thumbprints in the assertion header | `x5t` (SHA-1, required by Entra as an identifier) and `x5t#S256` |
| getrandom | All secrets generated by the program | Operating system CSPRNG |

No cryptography is implemented in this project's own code.

## Algorithms and parameters

| Where | Algorithm | Strength |
| --- | --- | --- |
| TLS versions | TLS 1.3 (TLS 1.2 only if `[tls] min_version = "1.2"`) | |
| TLS key exchange | `prefer` (default): X25519MLKEM768, then X25519, secp384r1, secp256r1. `require`: only X25519MLKEM768 and secp256r1MLKEM768 (`src/tls.rs`) | ≥128-bit classical, ML-KEM-768 post-quantum |
| TLS 1.3 cipher suites | TLS13_AES_256_GCM_SHA384, TLS13_AES_128_GCM_SHA256, TLS13_CHACHA20_POLY1305_SHA256 | AEAD, forward secrecy |
| TLS 1.2 cipher suites (only with `min_version = "1.2"`) | ECDHE with AES-GCM or ChaCha20-Poly1305, ECDSA or RSA certificates; no CBC, no RSA key exchange | AEAD, forward secrecy |
| Entra client authentication | JWT client assertion, RS256 (RSA-PKCS1v1.5 signature with SHA-256), valid 10 minutes, unique `jti` | RSA 3072 = 128-bit |
| Webhook signature | HMAC-SHA-256 over `timestamp.body`; secret at least 16 characters | 256-bit MAC |
| GUI secrets | Session ids, login link, form token: 256 random bits each, compared in constant time | 256-bit |
| Event and exception ids | UUID v4 | Identifiers, not secrets |

Not used: MD5, SHA-1 for any security function, DES, RC4, ECB, CBC, PKCS#1 v1.5 encryption,
password hashing (no passwords are stored).

## Keys, certificates and secrets

| Item | Created by | Stored | Lifetime | Rotation | Destruction |
| --- | --- | --- | --- | --- | --- |
| Entra certificate and private key (provisioning app) | `install` on the host (rcgen) or `openssl` | `/etc/afas-entra-sync/key.pem`, 0600, service user | 365 days | `install --renew-cert`, upload the new `cert.pem`, remove the old one in Entra after a good run | `uninstall --purge`; remove the certificate from the app registration |
| Entra certificates for the modules (roles, joiner, leaver) | `openssl` on the host (docs/MODULES.md) | `/etc/afas-entra-sync/<module>-key.pem`, 0600 | 365 days | Same as above, per app registration | Same as above |
| Entra client secret (optional, not recommended) | Entra | Environment variable from the scheduler's secret store | Set in Entra (≤ 6 months advised) | New secret in Entra, update the secret store | Delete in Entra |
| AFAS token | AFAS Profit | `/etc/afas-entra-sync/afas.token` 0600, or an environment variable | Until revoked in AFAS | `install --replace-token` | Revoke in AFAS; `uninstall --purge` |
| Webhook secret | You (`openssl rand -hex 32`) | Environment variable or 0600 file | Until changed | Change on both sides at the same time | Remove from both sides |
| OAuth access tokens | Entra | Memory only | About 1 hour | Refreshed automatically | Process exit |
| GUI session ids, login link, form token | The GUI (getrandom) | Memory; the login link also in `gui-login-url` (0600) | Session: 30 min idle, 8 h max; link: 15 min, one use | Every sign-in; every restart | Sign-out, expiry, restart |

## Key management rules

Based on NIST SP 800-57 Part 1:

- **Generation**: private keys are generated on the host that uses them and never leave it.
- **Storage**: private keys and tokens are files with mode 0600, owned by the service user
  or root. The program refuses to start otherwise.
- **Use**: one key per app registration (provisioning app and each module), so a
  compromised key reaches only that registration's permissions.
- **Cryptoperiod**: certificates at most one year. Put the expiry date in the team calendar
  with a month's margin.
- **Compromise**: remove the certificate from the app registration in Entra (immediate
  effect), generate a new key, upload the new certificate, review the app's sign-in and
  audit logs.
- **Destruction**: `uninstall --purge` deletes keys, tokens and state.

## Crypto agility

- TLS version and post-quantum mode are configuration (`[tls]`).
- Algorithms and suites come from the rustls provider and change with library updates.
- Moving the client assertion to another algorithm (e.g. PS256) is a change in
  `src/entra.rs` only. The webhook MAC is in `src/modules/webhook.rs`.
